# AI Career Companion — 后端设计文档

## 概述

基于 FastAPI + WebSocket 的 Python 后端服务，与 React 前端配合使用。后端负责会话管理、LLM 流式对话、情绪分析数据聚合、用户简历数据存取，以及碎片化消息发送。

**设计原则**：
- 后端不依赖项目的 Agent 架构（BrainAgent / WorkAgent / EmotionAgent / ConversationContext）
- 通过 `LLMClient` 直接调用 DeepSeek API 进行流式对话
- 会话数据使用简单 dict 结构存储，不引入 ConversationContext
- FragmentStreamer 负责 `<split/>` 标记检测，实现碎片化消息发送
- 端口 8080，CORS 允许前端 Vite 开发服务器 (5173)

## 3. WebSocket API 规范

### 3.1 连接

```
ws://localhost:8080/ws/{session_id}
```

- 一个 `session_id` 对应一个 WebSocket 连接
- 连接建立时不做 session 验证（session 由 REST 创建）
- 断开时自动清理连接，但保留 session 数据

### 3.2 消息格式

所有消息使用 JSON envelope：

```json
{
  "type": "message_type",
  "content": "...",
  "data": {},
  "message": "...",
  "phase": "...",
  "agent": "..."
}
```

### 3.3 Server → Client 消息类型

| type | 方向 | 说明 | 负载字段 |
|------|------|------|----------|
| `dialogue` | S→C | Brain 对话回应文本 | `content`, `agent` |
| `token` | S→C | LLM 流式输出的单个 token | `content` |
| `fragment_break` | S→C | 标记消息气泡分割点 | 无负载 |
| `done` | S→C | 本次回复流结束 | 无负载 |
| `error` | S→C | 错误信息 | `message` |
| `status` | S→C | 处理阶段状态 | `phase` ("analyzing"\|"responding"), `agent` |
| `demand_analysis` | S→C | 需求分析结果 | `data` (demand_type, confidence, emotions, 等) |
| `pong` | S→C | 心跳响应 | 无负载 |

### 3.4 Client → Server 消息类型

| type | 方向 | 说明 | 负载字段 |
|------|------|------|----------|
| `chat` | C→S | 用户发送消息 | `content` |
| `ping` | C→S | 心跳检测 | 无负载 |

### 3.5 完整消息流示例

```
Client → Server:
  {"type": "chat", "content": "我明天有面试，好紧张"}

Server → Client (sequence):
  1. {"type": "status", "phase": "analyzing", "agent": "brain"}
  2. {"type": "demand_analysis", "data": {
        "demand_type": "emotional",
        "confidence": 0.92,
        "emotions": [{"label": "紧张", "intensity": "high"}],
        "overall_state": "negative",
        "support_intensity": "high"
     }}
  3. {"type": "dialogue", "content": "我理解你的紧张...", "agent": "brain"}
  4. {"type": "status", "phase": "responding", "agent": "emotion"}
  5. {"type": "token", "content": "我能"}
  6. {"type": "token", "content": "感受到"}
  7. {"type": "token", "content": "你的"}
  ...
  8. {"type": "fragment_break"}           ← 第一个气泡结束
  9. {"type": "token", "content": "面试"}
  10. {"type": "token", "content": "前紧张"}
  ...
  11. {"type": "fragment_break"}          ← 第二个气泡结束
  12. {"type": "token", "content": "深呼吸"}
  ...
  13. {"type": "done"}                    ← 流结束
```

### 3.6 碎片化消息流程

```
LLM 输出: "我能感受到你的紧张<split/>面试前紧张很正常<split/>让我们先深呼吸..."

FragmentStreamer 处理后发送:
  token: "我能"
  token: "感受到"
  token: "你的"
  token: "紧张"
  fragment_break          ← 前端封存当前气泡，创建新气泡
  token: "面试"
  token: "前紧张"
  token: "很正常"
  fragment_break          ← 前端封存当前气泡，创建新气泡
  token: "让我们"
  token: "先深呼吸"
  ...
  done
```

前端收到 `fragment_break` 后：
1. 将当前流式气泡标记为 `isStreaming: false`（封存）
2. 创建新的空流式气泡（显示呼吸动画）
3. 后续 `token` 写入新气泡

## 4. 数据模型与会话结构

### 4.1 会话数据结构（替代 ConversationContext）

每个会话使用简单 dict 存储：

```python
session = {
    "session_id": "a1b2c3d4e5f6",
    "user_id": "default_user",
    "created_at": "2026-05-10T15:30:00.123456",

    # 对话历史
    "history": [
        {"role": "user", "content": "你好", "timestamp": "..."},
        {"role": "assistant", "content": "你好！我是AI职业助手...", "timestamp": "..."},
    ],

    # 情绪分析历史 (每轮 LLM 需求分析的结果)
    "emotion_history": [
        {
            "emotions": [{"label": "紧张", "intensity": "high"}],
            "overall_state": "negative",
            "support_intensity": "high",
            "demand_type": "emotional",
            "confidence": 0.92,
            "timestamp": "2026-05-10T15:30:00.000000"
        }
    ],

    # 情绪标签历史 (从中文情绪标签映射的英文类别)
    "mood_history": [
        {"category": "anxious", "trigger": "我明天有面试好紧张", "timestamp": "..."}
    ],

    # 用户画像 (被动提取 + 手动编辑)
    "user_profile": {
        "grade_level": None,
        "major": None,
        "school": None,
        "target_role": None,
        "job_search_stage": None,
        "skill_focus": [],
        "common_concerns": [],
        "background_summary": None,
    }
}
```

### 4.2 会话操作

```python
class SessionStore:
    def create(user_id: str) -> dict          # 创建新 session dict
    def get(session_id: str) -> dict | None   # 获取 session dict
    def get_info(session_id: str) -> dict     # 获取 session 元数据
    def delete(session_id: str) -> bool        # 删除 session
    def list_sessions() -> list[dict]          # 列出所有 session 元数据
```

### 4.3 存储说明

- **存储方式**: 内存 dict（前期），单进程内有效
- **持久化**: 无（前期不做持久化）。后期可迁移到 SQLite / Redis
- **并发**: 前期无并发控制（假设串行访问）
- **清理**: 服务关闭时（lifespan shutdown）清理所有 session

### 5.3 上下文构建

流式处理器根据会话数据构建 LLM 调用上下文：

```python
context_parts = []

# 用户画像
profile = session["user_profile"]
if profile.get("grade_level"):
    context_parts.append(f"年级：{profile['grade_level']}")
if profile.get("major"):
    context_parts.append(f"专业：{profile['major']}")
# ...

# 近期对话历史（最近 5 轮）
history = get_recent_history(session["history"], max_turns=5)

# 情绪状态（如果存在）
last_emotion = session["emotion_history"][-1] if session["emotion_history"] else None

context_str = "\n\n".join(context_parts)
```

### 5.4 流式处理器设计（新建模块）

`streaming_handler.py` 替代当前 `agent_pipeline.py` 的功能：

```python
class StreamingHandler:
    """简化的流式处理器 — 不依赖 Agent 架构"""

    def __init__(self, llm_client, session: dict):
        self.llm = llm_client
        self.session = session

    async def handle_chat(self, user_input: str, send_json):
        # 1. 发送分析阶段状态
        await send_json({"type": "status", "phase": "analyzing"})

        # 2. LLM 需求分析 (chat_json)
        demand_analysis = await self._analyze_demand(user_input)

        # 3. 发送分析结果
        await send_json({"type": "demand_analysis", "data": demand_analysis})

        # 4. 发送 dialogue (Brain 简短回应)
        await send_json({"type": "dialogue", "content": ..., "agent": "brain"})

        # 5. 流式回应正文
        await send_json({"type": "status", "phase": "responding"})

        streamer = FragmentStreamer(send_json)
        async for token in self.llm.stream_chat(
            system_prompt=SYSTEM_PROMPT,
            user_input=user_input,
            context=context_str,
        ):
            await streamer.feed(token)
        await streamer.flush()

        # 6. 完成
        await send_json({"type": "done"})
```

### 5.5 需求分析

`_analyze_demand()` 使用 `LLMClient.chat_json()` 对用户输入进行结构化分析：

```python
ANALYSIS_PROMPT = """分析用户的输入，返回 JSON：
{
  "demand_type": "job_related|emotional|mixed|unknown",

  "overall_state": "positive|negative|neutral",

}"""
```

分析结果写入 `session["emotion_history"]`。

## 6. 碎片化发送设计

### 6.1 FragmentStreamer 状态机

`fragment_streamer.py` 中的 `FragmentStreamer` 类实现 `<split/>` 标记检测和气泡分割。

```
                  ┌──────────────┐
                  │    token     │
                  └──────┬───────┘
                         ▼
                  ┌──────────────┐
                  │ 追加到 buffer │
                  └──────┬───────┘
                         ▼
              ┌─────────────────────┐
              │ buffer 含 <split/> ? │
              └──────┬──────┬───────┘
                   是│      │否
                     ▼      ▼
          ┌─────────────┐  ┌──────────────────┐
          │ fragment     │  │ _safe_prefix_len │
          │ count >= 6 ? │  │ 安全前缀发送      │
          └──┬──────┬───┘  │ 保留可能形成标记  │
           是│      │否     │ 的后缀在 buffer   │
             ▼      ▼      └──────────────────┘
      ┌──────────┐ ┌──────────────┐
      │ 标记作为  │ │ 发送 before  │
      │ 普通文本  │ │ 发送 fragment│
      │ 忽略处理  │ │ _break       │
      │          │ │ fragment_count│
      └──────────┘ │ += 1         │
                   │ buffer = after│
                   └──────────────┘
```

### 6.2 关键算法

**`_safe_prefix_len(text)`** — 前缀匹配算法：

检测 buffer 结尾是否匹配 `<split/>` 的任何前缀（`<`, `<s`, `<sp`, `<spl`, `<spli`, `<split`, `<split/`）。若匹配则排除该后缀，返回安全可发送的长度。这防止 `<split/>` 标记被 LLM 的 token 边界切分时漏检。

```
text = "...今天先聊到这里<spl"
                               ↑ 匹配前缀 "<spl"
_safe_prefix_len → len(text) - 4  (保留 "<spl" 在 buffer)
```

**边界情况处理**：

| 场景 | 处理方式 |
|------|----------|
| 标记在 token 中间 | `MARKER in buffer` 直接检测 |
| 标记跨 token 边界 | `_safe_prefix_len` 保留部分前缀在 buffer |
| 连续多个标记 | 每个标记独立处理，依次 split |
| 标记在流开头 | before 为空，直接发 fragment_break |
| 标记在流结尾 | flush() 时 after 为空 |
| 超过 MAX_FRAGMENTS(6) | 剩余标记当普通文本，不再分割 |

### 6.3 硬限制

| 参数 | 值 | 说明 |
|------|-----|------|
| `MAX_FRAGMENTS` | 6 | 最多 6 个气泡（≤5 个 `<split/>`） |
| `MARKER` | `"<split/>"` | 标记字符串 |

双重防护：Prompt 约束（3-4 标记 + 单主题）+ Backend 硬限制（MAX_FRAGMENTS = 6）。

### 7.1 SessionStore

```python
class SessionStore:
    """线程安全的内存会话存储"""

    def __init__(self):
        self._sessions: Dict[str, dict] = {}       # session_id → 会话数据
        self._created_at: Dict[str, str] = {}       # session_id → ISO 时间戳

    def get(self, session_id: str) -> dict | None
    def get_info(self, session_id: str) -> dict | None
    def delete(self, session_id: str) -> bool
    def list_sessions(self) -> list[dict]
```

### 7.2 会话生命周期

```
1. 前端加载 → POST /api/sessions → 获得 session_id

3. 用户聊天 → WebSocket {"type": "chat", "content": "..."}

5. 重复步骤 3-4
6. 会话结束 → DELETE /api/sessions/{session_id} 或服务关闭
```

## 8. WebSocket 连接管理

### 8.1 WsManager

```python
class WsManager:
    """管理 WebSocket 连接"""

    def __init__(self):
        self._connections: Dict[str, Set[WebSocket]] = {}  # session_id → 连接集合

    async def connect(session_id, ws)        # 接受连接并注册
    async def disconnect(session_id, ws)     # 移除断开连接
    async def send_personal(session_id, data) # 向 session 的所有连接发送消息
    async def broadcast(data)                # 向所有连接广播
```

**不再包含**：
- `_pipelines` dict（移除）
- `set_pipeline()` / `get_pipeline()` / `remove_pipeline()`（移除）

### 8.2 连接生命周期

```
1. Client 发起 ws://localhost:8080/ws/{session_id}
2. ws_manager.connect(session_id, ws)
   - await ws.accept()
   - 将 ws 添加到 connections[session_id]
3. 消息循环 (while True):
   - 接收消息 → 处理 → 发送回应
4. Client 断开或异常:
   - ws_manager.disconnect(session_id, ws)
   - 清理连接记录
```

### 8.3 连接清理

- **主动断开**: `WebSocketDisconnect` 异常 → `ws_manager.disconnect()`
- **服务关闭**: lifespan shutdown → 遍历 active_sessions → 清理
- **session 删除**: DELETE /api/sessions/{id} → `ws_manager.disconnect()` + `session_store.delete()`

## 9. 错误处理与容错

### 9.1 WebSocket 错误

| 场景 | 处理 | 返回消息 |
|------|------|----------|
| JSON 解析失败 | 忽略，返回错误 | `{"type": "error", "message": "Invalid JSON"}` |
| LLM 客户端未配置 | 不处理，返回错误 | `{"type": "error", "message": "LLM 服务未配置 (DEEPSEEK_API_KEY 缺失)"}` |
| 会话不存在 | 不处理，返回错误 | `{"type": "error", "message": "会话未找到，请刷新页面重新创建"}` |
| 未知消息类型 | 忽略，返回错误 | `{"type": "error", "message": "Unknown message type: ..."}` |
| LLM 流式错误 | 日志记录 + 返回错误 | `{"type": "error", "message": "..."}` |
| WebSocket 断开 | 静默清理 | 不发送消息 |

### 9.2 REST 错误

| 场景 | HTTP 状态码 | 响应 |
|------|-------------|------|
| 会话不存在 | 404 | `{"detail": "Session not found"}` |

### 9.3 LLM 调用失败

- **连接失败**: 返回 `"LLM 服务未配置"` 错误
- **API 超时**: 依赖 `LLMClient` 内部处理（底层使用 httpx 超时配置）
- **API 返回错误**: 通过 `LLMClient` 的异常机制传递

### 9.4 容错策略（前期简化）

- **无重试**: LLM 调用失败后直接返回错误，不自动重试
- **无降级**: 不使用预制回答模板
- **无熔断**: 不限制连续错误次数
- **人工恢复**: 用户刷新页面重新创建会话即可恢复

## 12. 与前端对接说明

### 12.1 消息流契约

前端 Store (`chatStore.ts`) 和 WebSocket Hook (`useWebSocket.ts`) 依赖以下消息类型：

| 消息类型 | 前端处理 |
|----------|----------|
| `token` | 追加到当前流式气泡内容末尾 |
| `fragment_break` | 封存当前气泡 → 创建新空流式气泡 |
| `done` | 封存当前气泡 → 标记流结束 |
| `dialogue` | 创建新的完整 AI 气泡 |
| `error` | 显示错误 toast/提示 |
| `status` | 更新处理阶段指示器 |
| `demand_analysis` | 更新侧栏情绪面板数据 |
| `pong` | 心跳计数更新 |

### 12.2 EmotionTab 数据流

```
EmotionTab (前端) ← GET /api/emotion/trends/{session_id}
    ↑
    │  后端从 session["emotion_history"] 构建数据
    │
WebSocket 聊天过程中
    → 每轮 LLM 需求分析结果写入 session["emotion_history"]
```

### 12.3 ResumeTab 数据流

```
ResumeTab (前端) ← GET /api/resume/{session_id}
    ↑                    ↑
    │ 读取               │ 更新
    │                    │
session["user_profile"] ──┘
    ↑                    ↑
    │ 被动提取           │ 手动编辑
    │ (LLM 分析)         │ (PATCH endpoint)
```

### 12.4 重构影响范围

前端代码不受后端重构影响 — WebSocket 消息格式和 REST API 端点保持不变。仅后端内部实现变更。
