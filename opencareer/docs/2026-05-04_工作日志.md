### Phase 3: Agent Pipeline Integration ✓

**目标**: 将 BrainAgent → WorkAgent/EmotionAgent 通过 WebSocket 管线连接，采用 judge-and-handoff 模式。

**核心架构决策**:
- BrainAgent 处理**所有**上下文副作用（用户轮次记录、情感分析、画像提取、Brain 轮次记录），通过 `process_user_request()` 完成
- Pipeline 复制下游 agent 的上下文构建逻辑，直接调用 `llm_client.stream_chat()` — **避免**通过下游 agent 的 `process_user_request()` 调用导致的重复上下文记录
- 流式传输完成后，Pipeline 将下游 agent 的轮次记录到上下文中

**BrainAgent 路由优先级**:
```
crisis → emotion_agent
high support_intensity → emotion_agent  
累计负面情绪 → emotion_agent
job_related → work_agent
emotional/mixed → emotion_agent
unknown → None (澄清)
```

**新建文件**:
- `demo/web_api/agent_pipeline.py` (~280 行)
  - `AgentPipeline.__init__`: 用共享 ConversationContext 创建所有三个 agent
  - `MockAgentRegistry`: 内联类，将 agent 名称字符串映射到 agent 实例
  - `_mock_call_skill_via_mcp`: MCP 技能调用的占位实现（MCP 服务器在 web 模式下未连接）
  - `process_message()`: 主入口 — Brain 分析需求 → 发送对话 + 需求分析 → 流式传输下游 agent 响应
  - `_stream_work_agent()`: 复制 WorkAgent 的上下文构建（话题检测、情绪校准、历史、画像），通过 LLM 流式传输
  - `_stream_emotion_agent()`: 复制 EmotionAgent 的上下文构建（情绪检测、心情记录、历史、趋势），通过 LLM 流式传输
  - `_detect_emotion()`: 从用户输入和需求分析中检测主要情绪类别

**已修改文件**:
- `server.py`: 用基于管线的方式替换了原始的聊天消息处理器 — 惰性初始化管线，调用 `pipeline.process_message()`
- `chatStore.ts`: 新增 `setDialogue`（替换最后的流式 AI 消息内容）、`setDemandAnalysis`（存储元数据）、`demandAnalysis` 状态
- `useWebSocket.ts`: 新增 `dialogue`（Brain 的回应）和 `demand_analysis`（元数据）消息处理器

**WebSocket 协议 v2**:
```
Server → Client:
  {"type": "dialogue", "content": "...", "agent": "brain"}
  {"type": "demand_analysis", "data": {"demand_type": "求职", "confidence": 0.85, "target_agent": "work_agent", ...}}
  {"type": "status", "phase": "responding", "agent": "work_agent"}
  {"type": "token", "content": "..."}
  {"type": "done"}
```

**消息流时序**:
1. 用户发送消息 → 前端立即创建空的 AI 消息占位符
2. BrainAgent 分析需求（非流式，约 2-3 秒）
3. `dialogue` 消息到达 → 替换占位符内容为 Brain 的回应
4. 下游 agent 流式传输 tokens → 追加到消息内容
5. `done` 消息 → 前端标记流式传输完成

**TypeScript 验证**: `npx tsc --noEmit` — 通过，零错误。

## 实现方式详解

### 流式传输架构

```
浏览器                     FastAPI (8080)                DeepSeek API
  |                            |                              |
  |-- WS: {"type":"chat"} -->  |                              |
  |                            |-- BrainAgent.process()       |
  |                            |   (非流式 LLM 调用)            |
  |  <-- WS: dialogue ------- |                              |
  |  <-- WS: demand_analysis -|                              |
  |                            |-- llm_client.stream_chat()   |
  |                            |   --  SSE POST 请求 -->      |
  |                            |   <-- data: token --------- |
  |  <-- WS: token ---------- |                              |
  |  <-- WS: token ---------- |                              |
  |  <-- WS: done ----------- |                              |
```

### 关键设计约束

1. **本地沙盒**: Python 必须控制本地机器资源（浏览器自动化、文件系统访问），浏览器仅作为展示层
2. **无数据库**: 所有状态使用内存 `SessionStore` — `ConversationContext` 实例通过 `session_id` 查找
3. **惰性初始化**: AgentPipeline（包含 3 个 agent + 提示缓存）仅在每个会话的第一条聊天消息时创建
4. **MCP 离线**: MCP 技能调用返回占位错误 — MCP 服务器在 web 模式下未连接

### 已解决问题

1. **管道与前端的消息类型不匹配**: Phase 2 的前端仅处理 `token`/`done`/`error`/`status`/`pong`。Phase 3 的管线新增了 `dialogue` 和 `demand_analysis` 消息类型。解决方案：向 `chatStore` 新增 `setDialogue` 和 `setDemandAnalysis` action，并在 `useWebSocket` 中添加对应的处理分支。

2. **管道消息流时序**: Brain 的 `dialogue` 在下游 tokens 之前到达前端。前端在 `dialogue` 到达时替换 AI 占位符内容，下游 tokens 随后正确追加。
