项目名称：OpenCareer（多智能体架构求职助手）
技术架构：LangChain + MCP (Model Context Protocol) + SKILLs

架构概述：
1. 最底层：基础对话系统（通过Prompt工程实现鼓励支持型与幽默朋友型风格）和记忆系统
2. 技术栈：LangChain（智能体编排）、MCP（技能工具协议）、SKILLs（模块化功能）
3. 核心原则：除最底层对话系统和记忆系统外，所有功能必须通过SKILL实现

智能体设计（4个智能体）：
1. 大脑（调度智能体）
   - 模型：DeepSeek小模型（API或本地部署）
   - 职责：调度其他三个智能体，根据用户需求调用相应代理
   - 调度逻辑：
     * 情感需求触发：关键词检测（压力、焦虑、开心等）、情感分析模型、用户主动触发
     * 求职需求触发：用户提出具体求职要求（技能提升、模拟面试等）
     * 日志触发：每N轮对话后、用户信息更新时、上下文快满时
   - 提示词文件：brain_prompt.txt - 包含调度逻辑的提示词，定义智能体角色、决策规则、调度策略
   - 实现要求：agent文件中需要有代码能加载和调用brain_prompt.txt中的提示词
   - 特点：轻量级，主要负责路由决策

2. 工作代理（功能智能体）
   - 职责：所有求职相关技能的实现（不含标*的暂不开发功能）
   - 具体功能：
     * 技能提升建议：分析技能缺口，推荐学习资源，设计学习计划
     * 学习计划督促：通过集成在架构中的定时任务调度器定期提醒
     * 模拟面试：文本对话形式，提供反馈和改进建议
     * 信息提炼辅助：配合日志代理提取求职信息
   - 提示词文件：work_agent_prompt.txt - 包含功能执行逻辑的提示词，定义工作代理角色、功能调用规则、响应模板
   - 实现要求：agent文件中需要有代码能加载和调用work_agent_prompt.txt中的提示词
   - 预留接口：岗位匹配、简历优化、简历投递（标*功能，留出代码空间）
   - 实现方式：装载多个SKILLs，每个功能对应一个SKILL

3. 情感代理（情感支持智能体）
   - 职责：分析用户情绪与压力，帮助用户舒缓压力、分享喜悦、满足日常聊天需求
   - 触发方式：由大脑调度，当检测到情感需求时激活
   - 提示词文件：emotion_agent_prompt.txt - 包含情感支持逻辑的提示词，定义情感代理角色、情绪识别规则、情感回应模板
   - 实现要求：agent文件中需要有代码能加载和调用emotion_agent_prompt.txt中的提示词
   - 实现方式：情感支持SKILL，包含情绪识别和响应逻辑

4. 日志代理（信息管理智能体）
   - 职责：提取上下文关键信息并存储进记忆系统
   - 触发时机：每N轮对话后、用户信息更新时、上下文快满时（由大脑调度）
   - 提炼字段：教育背景、工作经验、技能列表、项目经历
   - 提示词文件：log_agent_prompt.txt - 包含信息提取逻辑的提示词，定义日志代理角色、信息提取规则、数据结构化模板
   - 实现要求：agent文件中需要有代码能加载和调用log_agent_prompt.txt中的提示词
   - 实现方式：信息提取SKILL，结构化存储数据

记忆系统设计：
- 存储数据类型：
  1. 用户个人信息（教育背景、工作经验、技能、项目经历）
  2. 对话历史（完整对话记录）
  3. 提炼的关键信息（结构化数据）
  4. 学习计划进度（任务完成情况）
- 存储方式：分文件保存，加密存储，确保隐私安全
- 检索机制：支持智能体按需查询和更新

并发架构设计：
- 设计原则：基于低并发（同时服务几个用户）、可接受短暂延迟、适度扩展的需求
- 大脑参与模式：大脑作为中央调度器始终参与工作流程，但采用异步非阻塞架构
- 同时工作能力：
  1. 单一用户场景：大脑根据需求类型调用一个或多个代理，代理可以异步并行工作
  2. 多用户场景：不同用户的请求由不同的大脑实例或线程处理，互不干扰
- 异步实现方案：
  1. 大脑接收用户输入后，异步调用相应代理，不阻塞等待结果
  2. 代理处理完成后，通过回调或消息队列将结果返回给大脑
  3. 大脑整合多个代理的结果，回复用户
- 互不干扰保障：
  1. 每个代理有独立的工作空间和资源
  2. 通过会话ID隔离不同用户的数据和状态
  3. 使用线程池或进程池管理代理执行
- 性能优化：
  1. 大脑使用轻量级小模型（DeepSeek），减少调度开销
  2. 代理采用懒加载机制，按需初始化和销毁
  3. 记忆系统支持并发读写，使用锁机制保证数据一致性
- 扩展性考虑：
  1. 未来如果并发增加，可以部署多个大脑实例，使用负载均衡
  2. 代理之间可以建立直接通信通道，减少大脑的调度负担
  3. 支持事件驱动架构，代理可以订阅感兴趣的事件

- 详细方案参考：有关并发架构的详细技术实现方案，请参阅《并发架构方案.txt》文档，其中包含完整的异步实现代码、资源管理策略、性能优化方案和扩展策略。

SKILLs设计规范：
1. 两种调用方式：
   - 自研SKILL：通过MCP Server调用，注册为LangChain可识别的Tools
   - 外部SKILL：从skillhub等平台复制指令安装
2. 模块化结构（每个SKILL必须遵循）：
   skill-name/
   ├── SKILL.md（必需）
   │   ├── YAML前置元数据（name、description为必填项）
   │   └── Markdown格式指令说明
   └── 捆绑资源（可选）
       ├── scripts/    - 确定性/重复性任务的可执行代码
       ├── references/ - 按需加载的文档资料
       └── assets/     - 输出所用文件（模板、图标、字体）
3. 开发要求：严格遵循结构，确保可插拔性

MCP Server设计：
- 实现语言：Python
- 功能：将SKILLs注册为可以被LangChain识别的Tools
- 要求：支持动态加载和卸载SKILLs

定时任务调度器：
- 实现方式：集成在架构中，作为系统核心组件
- 功能：定期检查学习计划进度，发送提醒
- 触发机制：可配置的时间间隔（如每天/每周）

测试策略：
1. 单元测试：每个SKILL和智能体组件的独立测试
2. 集成测试：智能体之间协作测试，MCP Server与SKILLs集成测试
3. 端到端测试：完整用户流程测试，模拟真实求职场景
4. 测试环境：使用test目录组织所有测试文件

部署与开发：
- 前期：终端调用测试，无需前端界面
- 后期：可扩展Web前端或GUI界面
- 开发流程：先实现核心智能体和SKILLs，再逐步添加功能

注意事项：
1. 隐私安全：所有用户数据加密存储，未经授权不得访问
2. 可扩展性：SKILLs模块化设计，便于新增功能
3. 兼容性：支持从skillhub等平台导入外部SKILLs
4. 代码质量：严格遵循SKILLs规范，确保可维护性
5. 提示词管理：每个智能体必须有专用的提示词文件，agent代码中需要有加载和调用提示词文件的逻辑，提示词文件使用.txt格式，包含智能体角色定义、行为规则和响应模板
