### 📝 备注

1. **实现原理**：当用户连续多轮表达负面情绪后提出工作需求，Brain Agent 会先调用 `conversation_context.get_accumulated_emotion_assessment()` 判断用户是否适合处理工作事务，若不适宜则覆盖原有 `demand_type == "job_related" → work_agent` 的路由逻辑，转而路由到 Emotion Agent 进行情感支持。

2. **积累数据来源**：
   - `emotion_history`：每轮 LLM 情感分析的结构化结果（emotions、overall_state、support_intensity）
   - `mood_history`：从中文情感标签（焦虑/沮丧/压力等）映射到英文情绪类别（anxious/discouraged/stressed）
   - 两者共同用于 `get_accumulated_emotion_assessment()` 的综合评估

3. **与现有路由优先级的关系**：积累情绪路由覆盖的优先级高于普通的 `job_related → work_agent`，但低于 `crisis/high` 强制情感支持（crisis 仍然走 force_support 路径）。

     - `MAX_FRAGMENTS = 6` 硬限制：超过 5 个标记后，后续标记当作文本忽略

   - TypeScript 类型检查通过（`npx tsc --noEmit`，零错误）
   - Python 语法检查通过（`fragment_streamer.py` + `agent_pipeline.py`）

### 📝 技术要点

1. **新消息类型**：`fragment_break`（Server → Client），不含数据负载，仅触发前端气泡切换
2. **FragmentStreamer 状态机逻辑**：
   - token 到达 → 追加到 buffer → 检测 `<split/>`
   - 未检测到标记：发送安全前缀（排除部分标记尾部），保留可能形成标记的后缀
   - 检测到标记：发送 before 部分 → 发送 `fragment_break` → 递增计数 → 保留 after 部分
   - 超过 MAX_FRAGMENTS：忽略剩余标记，所有内容当普通文本
3. **regenerate 兼容**：`removeLastMessage` 的 while 循环确保清除所有碎片化 AI 气泡 + 触发 user 消息
4. **信息过载双重防护**：Prompt 层（最多 4-5 气泡 + 单主题）+ Backend 层（MAX_FRAGMENTS = 6）
