# 中文简历 ATS 优化指南

目标：让中文简历在 ATS 中可解析、可匹配、可排序，同时保持人工阅读体验。

## ATS 在中文场景下看什么

1. 是否能正确解析基础字段：姓名、联系方式、教育、经历、技能。
2. 是否命中 JD 关键词：岗位词、技能词、行业词、能力词。
3. 是否具备结果证据：可量化成果与真实项目信息。
4. 是否格式规范：单栏、标准标题、可复制文本。

## 中文 ATS 友好格式

### 建议做法

1. 单栏布局，左对齐。
2. 使用标准标题：个人信息、职业摘要、工作经历、项目经历、教育背景、技能清单。
3. 字体选常见中文字体，导出后保证文本可复制。
4. 日期格式统一：2021.06-2024.03 或 2021/06-2024/03。
5. 每段经历使用短句要点，不用长段落。

### 避免做法

1. 多栏、表格、文本框。
2. 图片化文字、图标替代文字。
3. 页眉页脚放联系方式或核心内容。
4. 生僻符号和复杂样式。
5. 使用“创意标题”替代标准模块名。

## 关键词策略（中文优先）

### 关键词来源

1. 岗位名称及同义词：高级后端工程师 / 后端开发工程师。
2. 必备技能：如 Java、Spring Boot、MySQL、Redis、微服务。
3. 业务与方法词：高并发、稳定性、性能优化、数据治理、A/B 测试。
4. 软硬结合词：跨团队协作、项目推进、需求拆解、交付管理。

### 布局位置

1. 职业摘要：放 3-5 个核心词。
2. 技能清单：完整覆盖关键技术词。
3. 工作经历：将关键词放在具体成果句里。
4. 项目经历：体现“场景 + 技术 + 结果”。

### 中文关键词规范

1. 同时写中英文术语：持续集成（CI）、持续交付（CD）。
2. 缩写首次出现写全称：服务等级目标（SLO）。
3. 避免堆词，关键词必须附着在事实和结果上。

## 五类岗位优化重点

1. 校招：项目技术栈、实习产出、课程基础关键词。
2. 社招初级：独立交付、问题定位、模块优化关键词。
3. 社招中高级：架构设计、稳定性治理、跨团队协作关键词。
4. 资深/管理岗：团队管理、组织机制、经营指标关键词。
5. 转行：可迁移能力、新方向项目证据关键词。

## 投递前 ATS 自测

1. 文本可复制测试
- 打开 PDF，尝试全选复制到记事本。
- 如果出现乱码或无法复制，需修复字体导出。

2. 模块识别测试
- 检查标题是否为标准中文模块名。
- 检查时间线是否按倒序且格式统一。

3. 关键词覆盖测试
- 核对 JD 必须项是否在摘要、技能、经历中均有体现。
- 核对至少 60% 要点包含结果或指标。

## 常见失败原因

1. 关键词只有技能列表里有，经历中没有证据。
2. 标题命名随意，ATS 无法正确分块。
3. PDF 实际是图片或字体缺失导致乱码。
4. 经历堆砌职责，没有结果导向。

## 输出建议

1. 每次投递保留一个“基础版”和一个“岗位定制版”。
2. 文件名规范：姓名_岗位_年份.pdf。
3. 双语投递时，中文与英文版本分别导出，避免混排影响解析。

## Balance: ATS vs. Human Readers

**Optimize for Both:**
- Use keywords naturally, not in lists
- Maintain compelling narratives
- Quantify achievements
- Tell coherent career story
- Ensure visual appeal once parsed

**The Goal:**
Pass ATS screening while creating a resume that impresses human recruiters. Well-optimized resumes serve both audiences.

**Final Check:**
- ✅ Can ATS parse it?
- ✅ Would a human enjoy reading it?
- ✅ Does it showcase qualifications compellingly?
